# RFC — F11 m_adj MR 族解锁路径

> **Status**: 待决策（默认推荐被动等 + 监控）
> **Date**: 2026-05-17
> **Related**: [v2.1 followup pipeline](2026-05-15-v2.1-followup-pipeline.md) F11 · [F13 RFC](2026-05-17-f13-third-sut-rfc.md)

---

## 1. 背景

NOETHER 8 个 MetaPattern 中：

| Code | Status | 阻塞原因 |
|------|--------|---------|
| m_inv / m_mono / m_conv / m_cmp | ✅ active | — |
| **m_adj**（adjoint） | 🚫 out-of-scope | OpenMOC 默认 build 不导出 adjoint flux |
| m_rev / m_dyn / m_rel | out-of-scope | 与本 SUT 域语义不匹配 |

m_adj 的论文卖点：**伴随方程**（adjoint equation）描述参数扰动对响应的灵敏度，是数值模拟领域**真正的物理对称**。如果能上线，会让论文从"演示 4 类 MR" → "覆盖 5 类含高级 MR"。

## 2. 三条解锁路径

### 路径 A — 被动等：OpenMOC 上游加 adjoint export

**优点**：
- 不分散精力
- OpenMOC 团队若加，所有现有 binding 自动受益

**缺点**：
- 不可控；OpenMOC 主仓最近 18 个月没有 adjoint 相关 commit
- 时间表完全外部决定

**适用**：论文发表前不依赖 m_adj 时

### 路径 B — 主动加：自己 patch OpenMOC 启用 adjoint

**优点**：
- 时间可控
- 顺带为 OpenMOC 社区贡献

**缺点**：
- 工时未知，可能 1-2 周深入 C++ + SWIG
- 需要熟悉 MOC 算法 + adjoint 解算的人手
- 维护成本：以后每次 OpenMOC upgrade 都要 rebase patch

**适用**：研究组 willing 投入数值计算工程师

### 路径 C — 换 SUT：选 SU2 / 其他 adjoint-native solver 作 F13

**优点**：
- **顺带解锁 F13** —— SU2 是 CFD adjoint-native，加跨域 + adjoint 一举两得
- 工时可估（~4 day SU2 接入）

**缺点**：
- 改变 F13 选型（默认 OpenMC → SU2，增加 ~3 day 风险）
- SU2 学习曲线 + 接入复杂度比 OpenMC 高

**适用**：F13 还没启动 + 论文需要 m_adj 的情形

## 3. 推荐路径

**短期（W11-W12）**：**路径 A 被动等**

- F13 走 OpenMC（最低风险），m_adj 暂保持 out-of-scope
- 论文里诚实写 "m_adj 待 SUT 升级；当前 4 类 active MetaPattern 已经验证 MR generation pipeline"
- 在 paper limitation 段提及"future work: with adjoint-capable solvers (SU2, MCNP) we expect to add the m_adj family"

**中期（W13+，如果论文 reviewer push）**：**路径 C 换/加 SUT**

- 在 OpenMOC 上保留 4 类 MetaPattern + OpenMC 强化 m_cmp 的现状下
- 加 SU2 作为 **第 4 SUT**（不是替换第 3 SUT），让 m_adj 在 SU2 上跑

**不推荐 路径 B**：太重，性价比低

## 4. 监控触发条件

cloud 端**每月检查一次** OpenMOC 上游：

```bash
# 检查 OpenMOC 主仓最近 commit 是否含 "adjoint"
gh api repos/mit-crpg/OpenMOC/commits --jq '.[].commit.message' | grep -i adjoint | head -5
```

若发现 adjoint 相关 commit → 评估 patch，决定是否拉到 metbench venv。

## 6. 不阻塞声明

无论选哪条路径，**v2.1 正式发版不依赖 m_adj 解锁**。当前 4 类 MetaPattern + 3 类 Discoverer + R-Case 复现 + Multi-LLM consensus 已是完整论文支撑。F11 是 nice-to-have 增量，不是 release blocker。
