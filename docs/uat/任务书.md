## 2. 目标

**用一句话**：验证 MetBench v2.1 候选版本是否满足发版标准，给出 **PASS / CONDITIONAL PASS / FAIL** 判定。

## 3. 做什么

### 3.1 装环境（首次约 30 min）

按 `docs/uat/setup-guide.md` 装：

- Linux 端：.NET 8 SDK + OpenMOC venv（一键脚本 `.claude/web-setup.sh`）
- Windows 端：VS 2022 + .NET 8 SDK + clone 仓库
- LLM API key（下发人单独提供 `.env` 内容；**不要** commit）

### 3.2 跑 45 个用例

按 `docs/uat/test-procedures.md` 一条条走，每个用例编号 UC-XX。

| 子类 | 用例数 | 平台 | 大概用时 |
|------|--------|------|---------|
| A. 管理 CRUD | 8 | Win (A1-A7) + Linux (A8) | 20 min |
| B. MR 测试主流程 | 9 | Win | 25 min |
| C. MR 发现 & 验证 | 9 | Linux (C1-C5) + Win (C6-C9) | 20 min |
| D. R-Case 自动复现 | 2 | Linux | 5 min |
| E. 可视化 & 报表 | 7 | Win (E1-E5) + Linux (E6-E7) | 25 min |
| F. 持久化 & schema | 5 | Linux | 5 min |
| G. 运营 & 性能 | 5 | Linux | 5 min |
| **合计** | **45** | 双端 | **~105 min** |

### 3.3 打分 + 留证据

把 [`docs/uat/reports/round-template/`](reports/round-template/) **整个目录复制**到 `docs/uat/reports/round-N-YYYYMMDD-<你的名字>/`，然后填写：

- `README.md` — 元信息（commit / 平台 / LLM / 工时）
- `acceptance-rubric-filled.md` — 复制 [`acceptance-rubric.md`](acceptance-rubric.md) 改名后逐行打 **✅ / ⚠️ / ❌**
- `evidence/` — 截图 + trx + 错误日志（zip 或散文件均可）
- `findings.md` — 每个 ❌ / 文档错误 / 改进点对应一行，链 GitHub Issue

### 3.4 交付（PR 流程）

通过 PR 把整个 round 目录提交到主仓：

```bash
git checkout -b uat-round-N-<你的名字>
git add docs/uat/reports/round-N-YYYYMMDD-<你的名字>/
git commit -m "uat: round-N report by <你的名字> — <PASS/CONDITIONAL/FAIL>"
git push -u origin uat-round-N-<你的名字>
```

PR 标题：`uat: round-N report — <PASS/CONDITIONAL/FAIL>`。
下发人 review → merge → 自动归档进仓库 `docs/uat/reports/`。

⚠️ Bug 报告**不**写在 `findings.md` 正文里，而是去开 GitHub Issue（自动模板 `UAT Finding`），`findings.md` 只写 issue 编号 + 一句话。详见 [`reports/README.md`](reports/README.md)。

## 4. 验收标准

### 4.1 任务本身的验收（下发人评测试员工作）

| 标准 | 通过条件 |
|------|---------|
| **完整性** | 45 个用例全部打分，没有空行 |
| **证据齐全** | 每个 ❌ 都有截图 / trx / 日志 |
| **复现性** | 任何 ❌ 都附可复现步骤 |
| **及时性** | 接受任务后 2 工作日内交付 |
| **总评填写** | 给出 PASS / CONDITIONAL PASS / FAIL + 理由 |

### 4.2 Release 通过准则（你给系统的判定）

| 系统判定 | 你应勾选 |
|---------|---------|
| 全部 ✅ 或仅 ⚠️ + ≤ 3 个 🟢 Minor ❌ | **PASS** ✅ |
| 有 🟡 Major ❌ 但 ≤ 5 个 + 都已有 fix 计划 | **CONDITIONAL PASS** ⚠️ |
| 有任一 🔴 Blocker ❌ 或 Major ❌ > 5 个 | **FAIL** ❌ |

阻断分类（acceptance-rubric 每行右侧已标）：

- 🔴 **Blocker** — 必须修；任一 ❌ 就 FAIL Release
- 🟡 **Major** — 应修；累计 ≥ 5 个 ❌ 就 FAIL Release
- 🟢 **Minor** — 可延期；不影响 Release
